Phase 1 — Identity Foundation & Account Provisioning

1. Objective

Establish a foundational identity structure for a simulated higher education institution using Microsoft Entra ID.

The implementation models six institutional identity populations and organizes them into security groups to support structured access management and future identity governance.

2. Environment

| Component | Configuration |
| Identity Platform | Microsoft Entra ID |
| Tenant | Personal Azure tenant |
| Directory Edition | Microsoft Entra ID Free |
| Identity Type | Cloud-only Member |
| Group Type | Security |
| Membership Type | Assigned |

4. Security Group Configuration

Six security groups were established.

| Security Group | Intended Population |
| SG-Faculty | Faculty |
| SG-Staff | Staff |
| SG-Students | Students |
| SG-IT-Support | IT Support |
| SG-IT-Privileged | Privileged Administrators |
| SG-Contractors | Contractors |

All groups use assigned membership and the Security group type.

5. Security Design Decisions

Identity Segmentation

Users are organized according to institutional responsibilities to support consistent access assignment.

Least Privilege

Users are not automatically granted administrative privileges based on their identity population.

Privileged Identity Separation

The privileged administrator population is modeled separately from standard workforce accounts. Membership in the privileged security group does not automatically grant an Entra directory administrator role.

Cloud-Only Identity

Cloud-only test accounts provide an isolated identity environment without external directory dependencies.

Synthetic Data

All accounts are fictional and used exclusively for portfolio testing.
